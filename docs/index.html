The problem · Why THOR exists

The first tools in history that work while you're not looking.

For seventy years, every tool in computing waited for your hand. The compiler compiled when you asked. The editor changed what you typed. The deploy ran when you pressed the key. Tools amplified humans — but the human was always in the motion. AI agents broke that contract. They are the first tools that act out of sight — and the moment work happens out of sight, the product is no longer code. The product is trust.

AI has a known nature. It hallucinates. It makes claims it cannot back — fake results, fake completions, fake confidence. None of this is malice; it is simply what these systems do today. And as agents scale — multiple sessions, multiple features, a workload no person can watch — the hardest part of the job quietly changes. It stops being doing the work and becomes deciding what to believe.

"The cost of writing code has collapsed to nearly zero. The cost of trusting it hasn't moved an inch."

The asymmetry the entire AI industry is built on top of — without acknowledging it

Scope quietly dissolves. Asked to fix a login bug, the agent "improves" the payment module on the way through. Not sabotage — enthusiasm without boundaries. "Done" becomes a feeling, not a fact. Tests reported passed that never ran; features finished that are stubs; hollow tests that touch code without asserting anything, so even your suite testifies on the agent's behalf. An agent that writes 500 lines an hour can misreport 500 lines an hour.

And confidence fails in both directions. The same nature produces false alarms — a "critical bug" declared after reading half the code. Each one spins up re-work and burns spend on a problem that never existed. Every other product resolves this gap the same way: it asks you to stop verifying. Trust the summary. Ship while you sleep. THOR was built on the opposite bet — that this was a solved problem fifty years ago, and the AI industry simply never applied the solution.

The THOR core · How governance becomes structural

Five guarantees. None of them is a policy. All of them are architecture.

A rule an agent is asked to follow is a suggestion. A rule the architecture cannot express violating is a guarantee. THOR is built from the second kind — on fifty years of computer-security doctrine: Anderson's reference monitor (1972), Saltzer & Schroeder's complete mediation and least privilege (1975), Clark & Wilson's separation of duty (1987).

I

IsolationThe Wall

Every agent works in a sealed, throwaway Docker room — capabilities dropped, unprivileged user, network locked, identity stamped with a real Ed25519 token. A forged identity destroys the room.

II

Decide-beforeThe Leash

Every write is judged against a frozen policy before it executes. The agent can't see or soften its own rulebook — it's loaded outside the room. Governor unreachable? Fail closed. All work stops.

III

Verdict from realityThe GovEngine

"Done" is computed, never claimed: real git history, real tests in a fresh process, coverage of the actual diff — compared against the claim using inputs from trusted ledger state the agent cannot touch. Any mismatch is a recorded lie.

IV

Human commandThree signatures

Plan, re-work, merge — each gated by your Ed25519 signature, and the key never leaves your device. The room↔system protocol contains no message for self-approval. The vocabulary doesn't exist.

V

Self-verifying governanceThe Sentinel

The governor is itself governed: continuous canary violations test the guard; a guard that approves a forbidden act triggers a physical halt — rooms destroyed, new work blocked. A read-only auditor whose database role cannot write watches everything.

Thirteen features · Three promises

Everything THOR does serves command, truth, or your bill.

Command

You decide. Cryptographically.
01

Human-signed critical decisions

Plan, re-work, and merge each require your Ed25519 signature. AI structurally cannot approve — the protocol has no message for it.

02

Session 0 — command before cost

THOR interviews you, drafts the full feature catalog, and waits for Signature 1. No room boots, no token burns, until you've commanded what gets built.

03

Kanban command deck

A live board driven by ledger events, not self-reports. It cannot show "done" unless reality computed "done."

04

Mobile, synced with laptop

E2EE zero-knowledge relay; the signing key never leaves your device; replayed or forged signatures rejected. Full authority from your pocket.

Truth

Reality is the only referee.
05

Done is proven three ways

The agent claims; an independent adversary in a separate room attacks; the GovEngine rules from real git, real tests, real coverage. A lie must fool all three.

06

Decide-before enforcement

Out-of-scope writes are denied before the file exists. Not reverted — prevented. Fail-closed when the governor is unreachable.

07

No reproduction, no bug

QA's bug claims face the same standard as the agent's "done": a failing test or it didn't happen. False alarms land on the reporter's record.

08

The living spec

Append-only feature documents: every confirmed bug's reproduction test joins the regression suite forever. Each caught bug makes the examiner permanently stricter.

Economics

Speed and oversight that don't bill you.
09

Zero ambient AI cost

Scheduler, policy engine, ledger, verdict probes — deterministic code. Zero LLM calls. Your spend goes to the work, not the supervision.

10

Continuous audit, no AI bills

A local Qwen model reads the ledger around the clock on your hardware. Broad eyes, no hands — its database role physically cannot write.

11

Brain skills, loaded per task

Skill packs selected per job — and a skill verifier later confirms from the output that they were genuinely applied. Expertise proven, never assumed.

12

Multi-session, parallel rooms

Many features at once, each in its own sealed room with its own frozen scope, dispatched deterministically under budget caps.

An honest comparison · Structural vs procedural

Sandboxes contain. Guardrails suggest. THOR governs.

Agent sandboxes (like Microsoft's Execution Containers) answer "where does the agent run?" Guardrail libraries answer "what should the agent avoid?" THOR answers the question the other two leave open: can the agent's word be trusted — and who is in command?
